# ゼミ質疑支援アプリ

研究室のゼミ（中間発表・期末発表レビュー）で使う質疑支援 Web アプリである．

聴衆がスマートフォンから匿名で質問を投稿し，質疑の場でそれを共感数順に消化する．
あわせて，聴衆が理解を見失った時刻を記録し，発表全体を通した理解度の推移として可視化する．

学生が挙手して質問する心理的な障壁を下げ，質疑を教員以外にも開くことを狙う．
発表者は「どこで伝わらなかったか」を記録として受け取れる．

---

## できること

- **匿名の質問投稿**．氏名・学籍番号・IPアドレスは一切保持しない
- **「わからん」の記録**．押した時刻を発表開始からの経過秒として残す
- **わからん率のグラフ**．30秒刻みで集計し，最も集中した区間を強調する
- **共感による並び替え**．共感数の多い質問から順に消化する
- **消化の管理**．答えた質問は末尾へ送る．押し間違えても戻せる
- **記録の出力**．質疑終了時に発表1件分の記録を Markdown で生成する
- **複数発表の連続進行**．1回のゼミで3〜5名が交代する運用を前提とする

## 画面

| 画面 | パス | 端末 | 内容 |
|---|---|---|---|
| 参加 | `/join` | スマートフォン | 学年を選ぶだけ．ゼミ開始時の1回のみ |
| 参加者 | `/live` | スマートフォン | 発表中は「わからん」と質問投稿，質疑中は一覧と共感 |
| 発表者 | `/present` | 発表者PC | QR，接続人数，質問件数，開始／終了の操作 |
| 質疑 | `/review` | スクリーン投影 | わからんグラフ，質問一覧，消化の操作 |

参加者の画面は発表の状態に応じてサーバから切り替わる．
**参加者に操作を求めるのは，最初の学年選択だけである．**

---

## 必要なもの

- Python 3.11 以上
- サーバPCと参加者の端末が**同じLANにいること**
- ブラウザ（iOS Safari 18以降，Android Chrome 111以降．発表者PCは Chrome）

外部への通信は行わない．CDN もオンラインフォントも使わないため，
インターネットに繋がらない会場でも動作する．

## セットアップ

```bash
python3 -m venv .venv
```

```bash
source .venv/bin/activate        # Windows: .venv\Scripts\activate
```

```bash
pip install -r requirements.txt
```

依存は `fastapi` / `uvicorn` / `httpx` / `qrcode` の4つだけである．
フロントエンドにビルドツールは使わない．`npm install` は不要である．

## 事前の疎通確認（最初に必ず実行する）

**学内 Wi-Fi でクライアント間通信（プライバシーセパレータ）が遮断されていると，
このアプリは一切動かない．** 会場で初めて気付くと打つ手がないため，先に確認する．

```bash
python3 tools/check_network.py
```

サーバPCで実行し，表示されたQRコードをスマートフォンで読む．
「届きました」と出れば問題ない．標準ライブラリのみで動くため，
`pip install` の前でも実行できる．

届かなかった場合は，ファイアウォール／別ネットワークへの接続／
プライバシーセパレータのどれが原因かを切り分ける手順が表示される．
プライバシーセパレータだった場合は，サーバPCのテザリングに参加者を繋ぐ運用に切り替える．

> QRの白黒が反転して読めないときは `--light-terminal` を付けて再実行する．
> ターミナルの背景色によって描き方が逆になるためである．

## 起動

```bash
SEMINAR_TITLE="中間発表レビュー" .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`--host 0.0.0.0` は必須である．これがないとスマートフォンから接続できない．

| 環境変数 | 既定値 | 内容 |
|---|---|---|
| `SEMINAR_TITLE` | `ゼミ` | 参加画面と発表者ビューに出る名前 |
| `SEMINAR_DATE` | 起動日 | 記録に載る日付 |

日付は記録に載る．後から中間発表と期末発表を並べるときに効くため，
既定のままでも空にはならない．

サーバPCのIPアドレスを確認する：

```bash
ipconfig getifaddr en0 || hostname -I     # Windows は ipconfig
```

### 注意

**`/present` は必ずLAN側のIPアドレスで開くこと．**
QRのホスト名はアクセスに使われたURLから組み立てるため，
`http://localhost:8000/present` で開くとQRも `localhost` を指し，
スマートフォンからは一切繋がらない．
`localhost` で開いた場合は画面に警告が出る．

**ゼミの最中にサーバを止めないこと．**
データはメモリにしか無く，再起動すると記録も参加者のトークンも全て消える．
参加者は学年の選び直しからやり直しになる（画面に案内は出る）．
設置する端末がスリープしない設定になっているかも確認する．

## 当日の進行

### 準備（ゼミ開始前）

1. サーバを起動する．セッションは自動生成されるので作成操作は要らない
2. 発表者PCで `http://<LANのIP>:8000/present` を開く．**`localhost` では開かない**
3. `/present` のQRをスクリーンに投影し，参加者に読ませる．学年を選べば参加は完了

質疑ビュー（`/review`）は，発表を開始すると**自動で別タブに開く**．
既に開いていれば開き直さないので，発表ごとにタブは増えない．
手で開きたいときは `/present` の「質疑ビューを別タブで開く」を押す．
ブラウザがポップアップをブロックした場合は画面に案内が出る．

### 発表1件ごとに繰り返す

4. 発表者が `/present` で氏名とタイトルを入れ，「この内容で発表を開始」
5. スクリーンはスライドに切り替える．参加者は「わからん」と質問を送る．
   **発表者ビューには件数しか出ない**（本文は出ない）
6. 発表が終わったら「発表終了（質疑へ）」．参加者の画面が自動で切り替わる
7. スクリーンを `/review` のタブに切り替える．上から順に読み，答えたら「消化」．
   **消化を押したときだけ並びが変わる**
8. 「質疑終了」で記録が出る．「記録をコピー」で控え，貼り付け先へ残す
9. 「次の発表を登録する」で 4 に戻る

前の発表者が終了操作を忘れても，次の発表を開始すれば自動的に閉じられる．

## 検証用のダミー参加者

**一人ではテストできない機能がある．** 共感による並び替えも，わからん率のグラフも，
複数人が同時に触らないと動作を確認できない．

```bash
.venv/bin/python tools/fake_audience.py --count 12
```

12人分の接続を張り，発表中はランダムな間隔で「わからん」と質問を送り，
質疑中は質問にランダムに共感する．セッションIDはサーバから自動で取得する．

| 引数 | 既定値 | 内容 |
|---|---|---|
| `--host` | `127.0.0.1:8000` | サーバの `host:port` |
| `--count` | `12` | 人数 |
| `--watch` | — | 受信したメッセージを全て表示する |

## 設計の要点

見た目には分からないが，**変更すると仕組みが壊れる**判断がいくつかある．

### 発表中は質問の本文を配信しない

発表者ビューに件数しか出さないだけでなく，**参加者の端末にも本文を送らない．**
質疑モードへ移った時点で初めて配信する．
発表者が発表しながら批判的な質問を読んで動揺することを防ぐための，意図した仕様である．
クライアント側で描画を抑止するのではなく，サーバが送らないことで担保している．

### 1名しかいない学年は「学生」に丸める

学年バッジ（B3／B4／M1／M2／D1／D2／D3／教員）を表示するが，
**その発表で投稿者が1名しかいない学年は「学生」に置き換える．**
研究室は小規模であり，丸めがないと学年表示が実名と同じ意味を持つ．
匿名性が壊れると質問が出なくなり，アプリの存在意義が失われる．
丸めはサーバ側で行い，生の学年をクライアントへ送らない．

### 並び替えは「消化」したときだけ

共感が入るたびに並べ替えると，質問を読んでいる最中にカードが動いて読めなくなる．
順位が新しいことと，画面が動いてよいことは別である．
共感数はその場で書き換わるが，**カードが動くのは消化した瞬間だけ**とした．
発表者が次へ進む合図であり，並びが変わってよい唯一のタイミングである．
経緯と根拠は `docs/ui-guidelines.md` に記載した．

### 書き込みは REST，配信は WebSocket

クライアントからサーバへの送信は全て HTTP POST で行う．
WebSocket はサーバからの一斉配信専用で，クライアントからは何も送らない．
この分離により，再接続が「繋ぎ直して受け直すだけ」で済む．

### ビルドツールを使わない

React も npm も Vite も使わない．素の HTML / CSS / JavaScript である．
並び替えの演出は View Transitions API を使うため，FLIP の自前実装も要らない．
`static/*.html` をブラウザで直接開ける状態を保っている．

## 本版で実装していないもの

- **Teams への自動投稿**．記録は発表者ビューの「記録をコピー」で残す．
  Webhook URL の取得の見込みが立たず，疎通を検証できないため見送った
- **データの永続化**．サーバを再起動すると全て消える．記録はコピーで残す
- **回答メモ**（発表者が後日，質問ごとに回答を記入する機能）
- **ユーザ認証**．学年を選ぶだけで参加する
- **不適切投稿の管理**．機能では防がない．運用上のルールとして事前に周知する

## 既知の制限

- 同時接続は25台を上限として想定している
- 記録のコピーは**全選択＋⌘C**（Windows は Ctrl+C）で行う．
  `http://<IP>:8000` は安全な文脈ではないため `navigator.clipboard` が使えない
- わからんの受付は同一参加者につき30秒に1回．超過分は黙って捨てる
- 質問の本文は200字以内
